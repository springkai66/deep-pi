# Pi 包目录搜索与 codemode 设置入口

## 已确认的需求

### Pi 包目录搜索

- 设置分类与搜索区域统一称为“Pi 资源包”，替代当前“Pi 扩展”名称。
- 搜索的唯一来源为 <https://pi.dev/packages>，以官网收录为准，包含社区作者发布的包。
- 覆盖官网目录的全部类型：扩展、技能、主题、提示模板，以及其他收录包。
- 沿用官网的名称、描述、作者匹配规则，默认按下载量排序。
- 关键词为空时，显示官网默认目录的热门包，沿用相同的排序与分页。
- 每批获取 50 个结果，通过“加载更多”追加后续结果；不能只在首页结果中进行本地过滤。
- 官网不可访问或搜索失败时，明确显示错误并提供重试；失败不得显示为“无匹配结果”，不得切换到其他搜索来源。

### codemode 设置入口

- 将当前“设置 → MCP 服务 → 已安装”中的 Codemode 设置移到“设置 → Pi 服务”，位于运行组件管理下方的独立设置区。
- 保留全局／当前项目切换、启用状态、运行模式、内联预算，以及现有继承与保存行为。
- Codemode 独立加载和保存；MCP 配置读取失败不得影响它。
- 无配置时默认启动关闭，保留已有用户设置；MCP 仍可按现有行为自动激活 Codemode。开关与说明明确默认启动语义。
- 保存后沿用重启已运行 Pi 任务才生效的提示；设置搜索能够找到 Codemode。
- 保留现有设置值与运行行为，不引入每个服务独立的 codemode 配置，也不迁移配置存储。

## 修复前诊断

### 搜索

修复前，前端通过 `search_pi_packages` 请求搜索，后端对 npm 的六种 Pi 关键词串行查询，每种最多读取第一页 250 条，再合并并按下载量排序。

- npm 的查询结果并不严格匹配用户关键词，应用也未再核验关键词匹配，导致无关包混入并可能排在前面。
- 任一次关键词查询失败都会丢弃此前成功得到的结果；搜索完整包名有精确查询兜底，`advisor` 这类关键词查询没有同等保障。
- 搜索失败只显示短暂提示，没有持久错误状态：页面可能显示无匹配结果，或保留旧查询结果。
- 搜索不读取后续分页，因此目录覆盖不完整。

线上核验中 npm 出现过 HTTP 429，但尚不能确认用户当时的失败就是限流。新搜索以官网目录为唯一来源，应由官网执行关键词匹配并提供对应分页，替换上述 npm 广泛搜索链路。

### Codemode

后端已独立位于 `src-tauri/src/pi_codemode.rs`，设置读写命令为 `pi_codemode_settings` 和 `save_pi_codemode_settings`。移动入口不需要迁移后端所有权。

- 全局配置：`%APPDATA%\com.deeppi.desktop\agents\pi\settings.json`。
- 项目配置：`<project>\.pi\settings.json`。
- 默认启动状态通过 `defaultTools` 的 `+codemode`／`-codemode` 表达。
- 模式位于 `codemode.mode`，取值 `on`／`only`，默认 `on`。
- 内联预算位于 `codemode.inlineBudget`，默认 3000，保存范围为 0–100000 的整数。
- MCP 自动激活是独立机制；本次保持 `mcp.json` 中 `autoEnableCodemode` 的现有语义。

原有 UI 把 Codemode 刷新放在 MCP 列表读取之后，MCP 配置错误会阻止刷新。搬迁时解除这个读取依赖。

## 验收场景

- 输入 `advisor`，能找到官网同一查询中的 `pi-advisor-flow`、`pi-advisor` 等包，结果来源和默认顺序与官网一致。
- 同一查询中的非扩展类型包也能出现，不因资源类型而被静默排除。
- 清空关键词后，切回官网默认目录，从第一批热门包开始展示。
- 查询超过 50 个结果时，可以加载后续结果；更换关键词时重置分页，旧查询的响应不能混入新结果。
- 查询确实无结果与官网请求失败分别显示；失败后可以重试当前查询。
- 在 Pi 服务中可查看和修改原有 codemode 设置，已有用户的值在入口移动前后保持一致。
- 无配置的 Codemode 默认启动开关为关闭；原有明确启用的配置仍显示为启用。
- 全局与项目范围均可读写；MCP 配置损坏时仍能加载和保存 Codemode。
- MCP 服务页不再显示 Codemode 设置；设置内搜索 Codemode 能定位到 Pi 服务。

## 实现与验证边界

- 搜索主要涉及 `src/lib/PiMarketplace.svelte`、`src-tauri/src/market.rs` 和设置导航文案。
- Codemode 入口主要涉及 `src/lib/PiMcpSkillsSettings.svelte`、`src/lib/PiSettings.svelte` 和 `src/lib/settings-navigation.ts`；复用现有后端命令。
- 更新搜索测试，覆盖官网目录解析、关键词查询、后续分页、真实空结果与请求失败、旧查询响应，以及全部资源类型。
- 更新现有 UI smoke 验证，将 Codemode 查找和保存场景移到 Pi 服务，覆盖作用域和独立于 MCP 配置的加载行为；保留后端 Codemode 配置测试。

本次设计没有需要单独 ADR 的难以逆转决策，需求与验收集中记录在本文，领域词汇记录在 `CONTEXT.md`。

## 官网核验

2026-10-08，<https://pi.dev/packages?name=advisor> 返回 25 个匹配包。官网搜索表单使用 `name` 参数，匹配名称、描述或作者；默认排序为 `downloads`，目录每页 50 个结果。目录数量和搜索结果会随发布变化，验收不固定包总数。
